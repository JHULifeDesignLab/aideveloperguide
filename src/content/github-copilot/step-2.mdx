## Goal
Move past autocomplete into Copilot's interactive features — and learn the context habits that determine whether they're sharp or generic.

---

## Copilot Chat

The chat panel answers questions with your code as context: explain this function, why does this test fail, how do I use this library. Two habits make it useful:

- **Scope with references.** Use `#file` and workspace references (and slash commands like `/explain`, `/fix`, `/tests`) to point at exactly the code you mean — the same context-controls-quality principle as everywhere on this site. Vague question over a whole repo → vague answer.
- **Use it to understand before you use it to generate.** Pointing chat at unfamiliar code and interrogating it is the highest-value, lowest-risk use of the whole feature set — and it builds the comprehension interviews test for.

---

## Edits: multi-file changes, supervised

Copilot's edit modes (names and capabilities move fast — see [the docs](https://docs.github.com/en/copilot) for the current state) take a task described in plain language and propose changes across multiple files, shown as diffs you accept file by file. The working rhythm is identical to what our [Cursor guide](/aideveloperguide/cursor) teaches: scope tightly, point at an example of the pattern you want, read every diff, and reset rather than argue when it goes sideways twice.

## Do this now (45 minutes)

Pick one small, real feature in a project. Run the full loop: ask chat to explain the relevant existing code → describe the change in edit mode, referencing a file that already does something similar → review each diff → run your tests. Note one thing the model needed told twice; that note feeds directly into Step 3.

---

## Check yourself

Done when you've used chat with explicit file references, landed one multi-file edit where you read every diff, and can articulate what context you gave — and what you had to add when the first answer came back generic.
