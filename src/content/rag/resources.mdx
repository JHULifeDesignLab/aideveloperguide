## Resources & Project Ideas

Everything below goes deeper than this guide can — official docs, evaluation tools, and project ideas, maintained by the people who build them. Use it in two ways: pull references while you build your RAG project, and mine the project ideas for a portfolio piece. A student who ships one RAG app from this list and can explain its retrieval tradeoffs walks into interviews with a story most applicants don't have.

### Foundational Reading

**[Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)** — Lewis et al. (2020)
The original RAG paper from Facebook AI. Not required reading before building, but worth skimming once you have hands-on experience. It contextualizes why RAG became the dominant approach for grounding LLMs in external knowledge.

**[Contextual Retrieval](https://www.anthropic.com/news/contextual-retrieval)** — Anthropic
Anthropic's technique for prepending generated context summaries to chunks before embedding. Measurable improvement in retrieval quality, especially for documents where chunks lack self-contained context. Required reading before building any serious RAG system.

### Core Documentation

**[LangChain RAG How-To Guides](https://python.langchain.com/docs/how_to/#qa-with-rag)**
The most complete set of practical examples. Covers document loaders, text splitters, retrievers, and end-to-end chains. Start here when you're building.

**[LlamaIndex RAG Guide](https://docs.llamaindex.ai/en/stable/getting_started/concepts/)**
Better conceptual explanations than LangChain's docs. Worth reading even if you use LangChain for implementation.

**[RAGAS Documentation](https://docs.ragas.io)**
The evaluation framework covered in Step 3. Walkthrough for setting up automated RAG evaluation with faithfulness, answer relevancy, and context recall metrics.

### Tools Reference

**[Chroma](https://docs.trychroma.com)** — local vector database, zero setup, great for development

**[Pinecone Quickstart](https://docs.pinecone.io/guides/get-started/quickstart)** — hosted vector DB for when you need scale or persistence without ops

**[pgvector](https://github.com/pgvector/pgvector)** — PostgreSQL extension for vector search; ideal if you're already using Postgres

**[rank_bm25](https://github.com/dorianbrown/rank_bm25)** — Python BM25 implementation for the sparse side of hybrid search

**[sentence-transformers cross-encoders](https://www.sbert.net/docs/cross_encoder/usage/usage.html)** — reranking models; `cross-encoder/ms-marco-MiniLM-L-6-v2` is a strong free option

### Project Ideas

<div className="bg-green-50 border border-green-200 rounded-lg p-5 my-6">
  <p className="font-semibold text-green-800 mb-2">Project 1 — RAG over your own documents</p>
  <p className="text-green-700 text-sm mb-3">Build a Q&A system over something you already have: class notes, a textbook PDF, a course syllabus, your own writing. Use LangChain + Chroma + Claude. The goal is to ask it questions and get answers that trace back to real content.</p>
  <p className="text-green-700 text-sm"><strong>Why this works as a portfolio project:</strong> it's a real dataset you understand, so you can evaluate answer quality accurately. You'll notice when it fails, which forces you to debug retrieval — and that debugging process is the learning.</p>
</div>

<div className="bg-green-50 border border-green-200 rounded-lg p-5 my-6">
  <p className="font-semibold text-green-800 mb-2">Project 2 — Add evaluation with RAGAS</p>
  <p className="text-green-700 text-sm mb-3">Take Project 1 and add automated evaluation. Write 10–20 test questions with known answers. Run RAGAS to measure faithfulness and context recall. Then try to improve the scores: adjust chunk size, add overlap, try different k values. Document what changed and by how much.</p>
  <p className="text-green-700 text-sm"><strong>Why this works:</strong> quantitative improvement is what separates engineering from tinkering. "I improved context recall from 0.6 to 0.82 by switching to hybrid search" is a concrete, defensible claim.</p>
</div>

<div className="bg-green-50 border border-green-200 rounded-lg p-5 my-6">
  <p className="font-semibold text-green-800 mb-2">Project 3 — Compare chunking strategies</p>
  <p className="text-green-700 text-sm mb-3">Take the same document and build three RAG pipelines with different chunking configurations: small chunks (256 tokens), medium (768 tokens), large (1500 tokens). Run the same test questions against all three and measure answer quality. Write up what you found.</p>
  <p className="text-green-700 text-sm"><strong>Why this works:</strong> chunking is the most important and least-discussed part of RAG. Demonstrating you've empirically compared strategies — not just followed a tutorial default — shows genuine understanding.</p>
</div>
