## About
RAG — Retrieval-Augmented Generation — is the technique that lets you build LLM applications that answer questions about *your* data. Not data the model was trained on. Your documents, your database, your knowledge base.

The core idea is simple: instead of hoping the model knows the answer, you fetch the relevant documents yourself, hand them to the model as context, and ask it to answer based on what you gave it. The model's job shifts from "know everything" to "reason about this specific information."

This guide is honest about the tradeoffs. RAG is powerful, but **retrieval quality determines answer quality**. The LLM cannot fix bad retrieval. If the wrong chunks come back, the answer will be wrong — confidently.

## Why RAG specifically?

Fine-tuning bakes knowledge into model weights — it's expensive, slow, and doesn't update dynamically. RAG injects knowledge at inference time. That means you can update your document set, re-embed, and the model immediately knows about the changes. No retraining.

For most applications that need to answer questions about custom data — internal docs, course materials, product manuals, codebases — RAG is the right tool. Fine-tuning is for changing *how* a model behaves, not *what* it knows.

## The progressive disclosure connection

RAG is a technical implementation of the same principle that makes Claude Code sessions and learning itself work: **don't give the model (or yourself) everything at once. Give it the relevant slice.**

A search engine retrieves the right documents. A teacher assigns the right chapter. RAG retrieves the right chunks. The common thread is scoping: narrow the information space before asking for reasoning. That discipline — filtering first, reasoning second — shows up everywhere in good engineering.
