## Resources & Project Ideas

Everything here comes from Render itself, so it stays accurate as the platform changes. Use the docs to unblock yourself while deploying, then work up the project ladder below — each level adds a production skill (health checks, databases, scheduled jobs) that most students can't claim. "Deployed and operated a full-stack app" is a resume line these projects let you say honestly.

### Official Documentation

- **[Render Documentation](https://render.com/docs)** — The official docs hub: web services, databases, static sites, cron jobs.
- **[Free Tier Details](https://render.com/docs/free)** — The source of truth for spin-down behavior and free database limits. Read this before relying on the free tier.
- **[Deploy FastAPI](https://render.com/docs/deploy-fastapi)** — Official quickstart for the most common student backend; Flask, Express, and Django versions are in the same docs section.
- **[Pricing](https://render.com/pricing)** — Current instance types and costs.

### Project Ideas

**Beginner**
- Deploy the API from any class project as a web service with a `/healthz` endpoint. Push a change, watch it auto-deploy, and document both URLs in the README.

**Intermediate**
- Give your RAG app a persistent home: FastAPI + Postgres on Render, with a nightly cron job that re-indexes documents. This is the "productionize one of your projects" path from the [Projects page](/aideveloperguide/resources/projects), started.

**Advanced**
- Build the full split-deployment: Vercel frontend, Render API + Postgres, an environment group for shared secrets, and a cron-scheduled eval run that writes scores to the database. Write the README as an architecture doc — every arrow labeled with *why*.
