## Cloud still matters — maybe more than ever

It's tempting to think that with AI doing so much of the work, infrastructure knowledge doesn't matter anymore. It's the opposite. Every AI product, every LLM API call, every vector database, every model deployment runs on cloud infrastructure. The industry doesn't just value cloud skills alongside AI — it expects them together.

Scalability is what separates a side project from something real. Cloud platforms give you managed compute, auto-scaling, logging, security, and global distribution out of the box. Learning this as a student means you can speak the language that engineering teams actually use on the job.

**Start with Google Cloud.** It has the most beginner-friendly learning path, gives you a verifiable skill badge after about an hour, and Vertex AI is increasingly relevant for anyone building with LLMs.

## Then pick a coding agent

Once you have some cloud grounding, add a coding agent to your daily workflow. These tools will meaningfully change how fast you write and understand code — but they're not all the same. Here's an honest comparison as of early 2026.

| | **Claude Code** | **Cursor** | **GitHub Copilot** | **IBM Bob** | **Amazon Q Developer** | 
|---|---|---|---|
| **Best for** | Agentic, multi-file tasks in terminal | In-editor AI with strong autocomplete | Inline suggestions inside VS Code / JetBrains | Modernizing legacy enterprise code (COBOL, PL/I, RPG, Java) | Existing AWS-centric work, including COBOL-to-Java mainframe modernization |
| **Pricing** | Usage-based (Anthropic API or Pro plan) | $20/mo for Pro | $10/mo, free for students | Free trial with 40 Bobcoins with option to subscribe to different plans from $20-$200 based on Bobcoins | Free tier and Pro at $19/user/month, with 4,000 lines of code per month for Java upgrades |
| **Strengths** | Deep reasoning, runs bash, reads your whole repo | Slick UX, fast inline edits, good chat | Lowest friction to start, familiar IDE feel | Governance and cost tracking (Bobalytics), mainframe and IBM i modernization, self-hosted or air-gapped deployment | Admin dashboard and per-user reports, mainframe modernization agents, free tier |
| **Weaknesses** | Can get expensive on large sessions; terminal-first | Proprietary, model quality varies by tier | Shallower reasoning, less useful for complex tasks | Usage priced in Bobcoins, with premium packages extra; named models and OpenShift unverified; enterprise-focused | IDE plugins reach end of support April 30, 2027, new signups ended May 15, 2026, and the latest models are Kiro-only |
| **Who it's for** | Developers comfortable in terminal, want an autonomous agent | Anyone who wants AI baked into their editor | Beginners, or anyone already deep in VS Code | Enterprise or consulting teams with legacy systems and compliance needs | Existing AWS users only; weak pick for new projects | 

No single tool wins for everyone. If you're already comfortable in the terminal, Claude Code pays off fast. If you want something that just works inside your editor from day one, start with Cursor or Copilot. If you want to try something new based on project specifics, take a look at IBM Bob or Amazon Q Developer. You can always add more later.

## A note before you start

These tools are genuinely powerful — and that's exactly why you shouldn't lean on them completely.

Coding is still important. Not because AI can't write code (it can, often well), but because you don't want to be a slave to your tools. If a model goes down, if pricing changes, if government regulation suddenly restricts LLM access, if a company shuts off an API — you don't want to be left with nothing. The developers who stay valuable are the ones who understand what the AI is doing, can catch its mistakes, and can work without it when they have to.

Use these tools to go faster. Not to avoid learning.
